1. 為什麼需要快取？

目前每次使用者查詢天氣，我們都會向 OpenWeatherMap 發送請求。這有幾個問題：

  • API 限制：免費版 API 有呼叫次數限制。
  • 延遲：網路請求需要時間，影響使用者體驗。
  • 資源浪費：天氣資料通常不會在幾分鐘內劇烈變化，重複查詢相同資料是浪費。

Flask-Caching 可以幫我們將 API 回應暫存在記憶體（或 Redis）中，下次查詢相同城市時直接回傳，無需再次呼叫 API。

1. 為什麼需要資料庫？

雖然我們可以直接從 API 取得天氣，但如果我們想要：

  • 讓使用者註冊帳號
  • 儲存使用者收藏的城市
  • 記錄搜尋歷史

我們就需要一個資料庫來持久化這些資料。

2. Flask-SQLAlchemy 簡介

Flask-SQLAlchemy 是 Flask 的擴充套件，它整合了 SQLAlchemy 這個強大的 ORM (Object Relational Mapper)。
ORM 讓我們可以用 Python 類別 (Class) 來操作資料庫，而不需要寫原生的 SQL 語法。

1. 為什麼要封裝 API 邏輯？

今天我們將建立一個專門的服務層來處理這些邏輯。

在 Day 06 中，我們使用了原生的 HTML 表單和 request.form 來處理資料。雖然可行，但存在幾個問題：

1. 什麼是 Jinja2？

Flask 預設使用 Jinja2 作為模板引擎。它允許我們在 HTML 中嵌入 Python 邏輯，動態生成網頁內容。
Jinja2 的核心概念是將「資料」與「呈現邏輯」分離，讓後端專注於處理資料，前端專注於頁面結構。
