30 天學習 Flask 計畫 - Weather App

專案概述

專案目標：使用 Flask 建立一個功能完整的天氣應用程式，整合天氣 API、資料視覺化與用戶管理功能。

第一週：基礎建立（Day 1-7）

Day 1 - 環境設定與 uv 管理

詳細內容 →
  • 使用 PowerShell 快速安裝 uv
  • 建立 Flask 專案：uv init flask_demo --python 3.14
  • 安裝 Flask 依賴：uv add flask
  • 撰寫第一個 Hello World 應用程式
  • Git 版本控制初始化

Day 2 - 建立基本 Flask Layout

詳細內容 →
  • 設定環境變數管理（python-dotenv）
  • 建立 Application Factory 模式
  • 專案結構組織：
    • flask_weather/ 應用程式主套件
    • routes/ 路由模組
    • templates/ Jinja2 模板
    • static/ CSS 樣式檔
    • tests/ 測試模組
  • 配置管理模組設定

Day 3：路由與請求處理

詳細內容 →
  • URL 路由基礎：使用 @app.route() 裝飾器定義路由
  • HTTP 方法（GET、POST）：處理表單提交與資料取得
  • 請求物件（Request Object）
    • request.args：URL 查詢參數
    • request.form：表單內容
    • request.method：請求方法判斷
  • 動態路由參數：/api/weather/<city> 語法
  • 錯誤處理：@app.errorhandler() 自定義 404、500 頁面

Day 4 - 藍圖系統與模組化 (Blueprints & Modularity)

詳細內容 →
  • 藍圖 (Blueprint) 基本概念：分離關注點、提升可複用性
  • 專案結構升級：
    • main/ - 主要頁面模組
    • weather/ - 天氣功能模組
    • auth/ - 用戶認證模組（後續開發）
  • 藍圖實作：
    • 建立藍圖物件：Blueprint('name', __name__)
    • 定義藍圖路由：@bp.route()
    • 註冊藍圖：app.register_blueprint()
  • URL 前綴與動態前綴：使用 url_prefix 參數
  • 路由分類與整合：
    • 首頁路由 → main 模組
    • 天氣查詢路由 → weather 模組（前綴 /weather）
  • 更新 Application Factory：在 create_app() 中註冊所有藍圖
  • 避免循環引用問題
  • 藍圖中的靜態檔案與模板配置

Day 5 - 模板引擎 Jinja2 基礎

詳細內容 →
  • 模板基礎語法 (Variables, Filters, Control Structures)
  • 建立基礎模板 (base.html) 與繼承機制
  • 整合 Tailwind CSS

Day 6 - 頁面設計與實作

詳細內容 →
  • 首頁模板設計 (index.html)
  • 天氣顯示卡片設計
  • 靜態檔案 (Static Files) 管理

Day 7 - 表單處理

  • 城市搜尋表單設計
  • Flask-WTF 表單驗證
  • CSRF 保護機制
  • 輸入驗證與錯誤訊息顯示 (flash messages)

第二週：API 整合與資料處理（Day 8-14）

Day 8 - 天氣 API 整合基礎

  • 註冊 OpenWeatherMap API
  • API 金鑰管理（.env）
  • 使用 requests 套件發送請求
  • 解析 JSON 回應資料

Day 9 - API 資料處理與錯誤控管

  • 封裝 API 呼叫邏輯
  • 處理 API 錯誤（401, 404, Rate Limit）
  • 資料格式化與單位轉換

Day 10 - 資料庫設定與 ORM

  • SQLite 資料庫配置
  • Flask-SQLAlchemy 初始化
  • 定義 User 資料模型

Day 11 - 資料模型與遷移

  • 定義 SavedCity 與 SearchHistory 模型
  • 建立模型關聯 (Relationships)
  • 使用 Flask-Migrate 進行資料庫遷移

Day 12 - 用戶註冊功能

  • 註冊表單設計
  • 密碼雜湊處理 (werkzeug.security)
  • 用戶資料寫入資料庫

Day 13 - 用戶登入與 Session

  • 登入表單設計
  • Flask-Login 整合
  • Session 管理與 User Loader
  • 登出功能

Day 14 - 資料快取機制

  • Flask-Caching 設定
  • API 回應快取策略
  • 減少外部 API 呼叫次數

第三週：Weather App 核心功能開發（Day 15-21）

Day 15 - 天氣查詢功能實作

  • 整合前端表單與後端 API
  • 顯示當前天氣資訊（溫度、濕度、風速）
  • 天氣圖示對應

Day 16 - 進階查詢功能

  • 攝氏/華氏溫度切換邏輯
  • 地理定位整合 (Geolocation API)
  • 根據座標查詢天氣

Day 17 - 多日天氣預報 API

  • 整合 5 Day / 3 Hour Forecast API
  • 預報資料結構解析
  • 資料分組與處理

Day 18 - 預報資料視覺化

  • 整合 Chart.js
  • 繪製溫度趨勢圖
  • 繪製降雨機率圖

Day 19 - 收藏城市功能

  • 收藏/取消收藏 API
  • 資料庫關聯操作
  • 限制未登入用戶權限

Day 20 - 收藏清單管理

  • 顯示用戶收藏城市列表
  • 批次查詢收藏城市天氣
  • 搜尋歷史記錄顯示

Day 21 - 進階天氣資訊

  • 空氣品質指數 (AQI) 整合
  • 日出日落時間計算與顯示
  • UV 指數與體感溫度

第四週：優化與部署（Day 22-30）

Day 22 - 前端互動優化

  • 響應式設計 (RWD) 調整
  • 使用 Alpine.js 處理前端互動
  • 載入動畫 (Loading Spinners)

Day 23 - 使用者體驗提升

  • 深色模式 (Dark Mode) 支援
  • 天氣背景動態變化
  • PWA 基礎配置 (manifest.json)

Day 24 - 安全性強化

  • SQL Injection 防護檢查
  • XSS 防護 (Jinja2 Autoescaping)
  • API 請求限流 (Flask-Limiter)

Day 25 - 效能優化

  • 資料庫查詢優化 (N+1 問題)
  • 靜態資源壓縮與快取
  • 分頁功能實作

Day 26 - 單元測試

  • 設定 pytest 環境
  • 撰寫 Model 單元測試
  • 測試 Helper Functions

Day 27 - 整合測試

  • API 路由測試
  • 表單提交測試
  • 測試覆蓋率報告

Day 28 - Docker 容器化

  • 撰寫 Dockerfile
  • 設定 docker-compose.yml
  • 容器環境變數配置

Day 29 - 雲端部署準備

  • 選擇部署平台 (Render/Railway)
  • PostgreSQL 資料庫遷移設定
  • Gunicorn WSGI Server 設定

Day 30 - 最終部署與文件

  • 部署至雲端平台
  • 設定 HTTPS 與網域
  • 撰寫最終 README.md 與 API 文件
