4. 效能考量 (N+1 API Calls)

目前的實作方式有一個嚴重的效能問題：如果使用者收藏了 10 個城市，載入 Dashboard 就需要呼叫 10 次 OpenWeatherMap API。這會導致頁面載入非常緩慢。

優化策略

  1. OpenWeatherMap Group API：官方有提供一次查詢多個城市 ID 的 API (/group)，但需要知道 City ID 而非名稱。
  2. **非同步載入 (AJAX)**：頁面先載入城市列表框架，然後用 JavaScript 逐個（或並行）去後端查詢天氣並填入。
  3. 後端並行處理：使用 Python 的 asyncio 或 ThreadPoolExecutor 並行發送請求。
  4. 依賴快取：我們在 Day 14 已經實作了 get_current_weather 的快取。只要快取還有效，速度就會很快。

為了簡化教學，我們目前依賴 快取機制。但在真實產品中，建議採用 AJAX 非同步載入 的方式，讓使用者先看到頁面，再看到天氣資料陸續出現。
