Day 24 - 安全性強化 (Security)

這是 30 天學習 Flask 計畫 - Weather App 的 Day 24 詳細內容
source code

1. 常見 Web 安全威脅

  • **SQL Injection (SQLi)**：攻擊者在輸入中夾帶 SQL 指令。
  • **XSS (Cross-Site Scripting)**：攻擊者在網頁中注入惡意腳本。
  • **CSRF (Cross-Site Request Forgery)**：攻擊者偽造使用者請求。
  • DDoS / Brute Force：暴力破解或癱瘓服務。

2. SQL Injection 防護

Flask-SQLAlchemy 使用 ORM，底層會自動對參數進行跳脫 (Escaping)，因此只要不使用原生 SQL 字串拼接，基本上是安全的。

5. 安全性標頭 (Security Headers)

使用 Flask-Talisman 可以快速設定 HTTP 安全標頭（如 HSTS, CSP）。已在 4.1 節的 create_app() 中配置。

5.1 常見的安全標頭

  • **Strict-Transport-Security (HSTS)**：強制使用 HTTPS
  • X-Content-Type-Options：防止 MIME 類型猜測
  • X-Frame-Options：防止點擊劫持（Clickjacking）
  • **Content-Security-Policy (CSP)**：防止 XSS 攻擊（生產環境建議配置）

Flask-Talisman 預設啟用所有保護，開發環境將 CSP 設為 None 以支援 CDN 資源。

5.2 檢查安全標頭

可透過瀏覽器開發者工具（F12）的「網路」分頁，查看回應標頭是否包含安全標頭：

實踐時間：45-60 分鐘

  1. 檢查程式碼中是否有原生 SQL 拼接。
  2. 檢查模板中是否有不必要的 | safe。
  3. 安裝 flask-limiter 並在登入路由上設定限制。
  4. 測試：連續快速登入失敗 5 次，確認是否會被封鎖 (429 Too Many Requests)。
  5. 安裝 flask-talisman 並啟用基本的安全標頭。
