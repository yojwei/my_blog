1. 資料庫查詢優化 (N+1 問題)

1.1 什麼是 N+1 問題？

假設我們有一個管理員頁面，要列出所有收藏紀錄及其作者：

總共會執行 1 + N 次查詢，這就是 N+1 問題。

1.2 使用 joinedload

SQLAlchemy 提供了 Eager Loading 機制，可以在一次查詢中把關聯資料抓回來。

這樣只會執行 1 次 SQL JOIN 查詢。

雖然我們的 Weather App 目前主要瓶頸在外部 API，但養成良好的 ORM 使用習慣非常重要。

2. 分頁功能 (Pagination)

如果使用者收藏了 50 個城市，Dashboard 頁面會變得非常長。我們應該使用分頁。

3. 靜態資源快取

瀏覽器會快取 CSS 和 JS 檔案。但如果我們更新了樣式，使用者可能會看到舊的版本。
Flask 預設會處理靜態檔案的快取控制，但我們可以透過「版本號」來強制更新。

3.1 檔案名稱雜湊 (Hashing)

Flask 內建支援靜態檔案雜湊。只要使用 url_for('static', filename='style.css')，Flask 會自動處理。
但在生產環境部署時，我們通常會希望更積極的快取策略（例如快取一年）。這部分通常交由 Nginx 或 CDN 處理（Day 30 會提到）。

實踐時間：45-60 分鐘

  1. 在 Dashboard 路由實作分頁邏輯。
  2. 在模板中加入分頁導航列。
  3. 測試：手動在資料庫新增多筆收藏資料（或暫時將 per_page 設為 1），確認分頁功能正常。
