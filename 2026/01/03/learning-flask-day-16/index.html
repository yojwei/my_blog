2. 溫度單位切換 (攝氏/華氏)

雖然國際標準多用攝氏，但提供單位切換能提升使用者體驗。

2.1 策略選擇

我們有兩種實作方式：

  1. 後端處理：在 Session 中記錄使用者的偏好單位，呼叫 API 時帶入 units=metric 或 units=imperial。
  2. 前端處理：API 統一回傳攝氏，由前端 JS 進行轉換顯示。

為了練習 Session 操作，我們選擇 後端處理。

2.3 快取與單位同步問題

由於在 1.3 已經將 get_current_weather 和 get_weather_by_coords 加上了 @cache.memoize() 裝飾器，當切換單位時，必須清除快取。

這是因為快取的 key 包含函數參數，但不包含 Session 的狀態。例如：

  • 呼叫 get_current_weather('Taipei') 時，快取內存的是該次呼叫的結果
  • 若只改變 Session 中的 units 值，下次呼叫相同參數仍會返回舊的快取（單位錯誤）

因此，2.2 節中的快取清除邏輯至關重要。

3. 測試重點

3.1 地理定位測試

  1. 基本功能：點擊定位按鈕，確認瀏覽器是否跳出權限請求
  2. 成功案例：授予權限後，應該正確顯示當前位置的天氣
  3. 失敗處理：
    • 拒絕權限時，應顯示錯誤訊息並恢復按鈕
    • 在不支援 Geolocation 的環境中，應提示使用者
  4. Loading 狀態：按鈕點擊後應顯示 spinner

3.2 單位切換測試

  1. 切換功能：在攝氏和華氏之間切換，確認數值變化正確
    • 0°C ≈ 32°F
    • 100°C ≈ 212°F
  2. 持久性：重新整理頁面後，單位設定應該保持
  3. 查詢功能：切換單位後進行新的查詢，應使用新單位
  4. 顯示一致性：確保所有溫度相關數值都使用相同單位

實踐時間：60-75 分鐘

  1. 在 config.py 設定 SECRET_KEY 和 OPENWEATHER_API_KEY
  2. 在 utils.py 實作 _fetch_weather_data 共用函數
  3. 修改 get_current_weather 和新增 get_weather_by_coords
  4. 在 main/routes.py 實作單位切換路由（包含快取清除邏輯）
  5. 在 weather/routes.py 實作座標查詢路由
  6. 在 index.html 加入定位按鈕與 JS 程式碼
  7. 在 base.html 加入單位切換下拉選單（使用 Alpine.js）
  8. 在 weather.html 更新溫度顯示邏輯
  9. 測試所有功能：
    • 點擊定位按鈕，確認是否能顯示所在地天氣
    • 切換單位，確認數值是否正確變化
    • 重新整理頁面，確認單位設定是否保持
    • 驗證同一位置在不同單位下的結果是否正確
